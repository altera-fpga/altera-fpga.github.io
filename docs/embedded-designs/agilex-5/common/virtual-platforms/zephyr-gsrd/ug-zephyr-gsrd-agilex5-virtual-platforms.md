

## Overview

This tutorial demonstrates how to build, package, and execute the Zephyr Real-Time Operating System (RTOS) on the virtual model of the Altera Agilex™ 5 E-Series Hard Processor System (HPS) using the [Intel Simics® Simulator](https://www.altera.com/products/development-tools/simics-virtual-platform). Simics enables comprehensive full-system simulation, allowing you to validate firmware, OS boot flows, and driver interactions before targeting physical silicon.

The Agilex 5 E-Series architecture pairs high-performance Arm Cortex-A55 and Cortex-A76 cores with rich HPS peripherals. Zephyr provides a modular RTOS footprint suited for real-time determinism applications.

The Arm Trusted Firmware (ATF) acts as the First-Stage Bootloader (FSBL) and Second-Stage Bootloader (SSBL) for Zephyr, as illustrated below:

![](./images/zephyr-boot-flow.png){:style="width:60%; display:block; margin-left:auto; margin-right:auto"}

Using the Agilex 5 E-Series Universal Virtual Platform (`agilex5e-universal.simics`), you can run production-ready Zephyr binaries with full visibility into HPS register states, peripheral interaction, and system execution without physical hardware.

**What you will learn**

* Setting up the Zephyr development environment and target Simics scripts.
* Compiling Zephyr images and boot components for the Agilex 5 HPS target.
* Booting compiled images via the Simics CLI using virtual QSPI memory and a serial console.
* Testing RTOS features on virtual peripheral targets.

## Pre-built Binaries

Pre-built binaries are available in the following [link](https://releases.rocketboards.org/2026.10/zephyr/agilex5_dk_a5e065bb32aea_zephyr/).

Binaries for a `Hello World` application and the `Shell Subsystem` (CLI) are provided in the release package under their respective folders (`hello_world` and `cli`). Both folders contain an identical layout described below:

| File Name                           | Description                                                                                                                                         |
|:------------------------------------|:----------------------------------------------------------------------------------------------------------------------------------------------------|
| `bl31.bin`                          | Arm Trusted Firmware (TF-A) Stage 3-1 raw binary (EL3 Runtime Firmware / PSCI implementation).                                                      |
| `zephyr.bin`                        | Final compiled raw binary executable of the Zephyr RTOS application.                                                                                |
| `qspi_boot/`                        | Directory containing boot images and configuration binaries for QSPI flash memory boot.                                                             |
| `baseline_a55.sof`                  | Quartus SRAM Object File containing the compiled FPGA fabric configuration bitstream for the Agilex 5 baseline design.                              |
| `baseline_a55_hps_auto.sof`         | Intermediate SRAM Object File automatically generated by Quartus PFG with the HPS First Stage Bootloader (`bl2.hex`) integrated into the bitstream. |
| `bl2.bin`                           | Arm Trusted Firmware (TF-A) Stage 2 raw binary (First Stage Bootloader / FSBL for the HPS).                                                         |
| `bl2.hex`                           | Intel HEX representation of `bl2.bin` generated via `objcopy`, consumed by Quartus PFG to embed BL2 into the SOF and flash image.                   |
| `fip.bin`                           | Firmware Image Package binary generated by `fiptool`, packaging the TF-A BL31 runtime firmware and Zephyr OS (`bl31.bin` + `zephyr.bin`).           |
| `qspi_flash_image_agilex5_boot.pfg` | Quartus Programming File Generator XML configuration specifying flash partitions, source bitstreams, raw binary payloads, and output targets.       |
| `qspi_image.jic`                    | JTAG Indirect Configuration file used by the Quartus Prime Programmer to write the complete boot image into target QSPI flash memory via JTAG.      |
| `qspi_image_jic.map`                | Memory map text file generated by Quartus PFG detailing flash partition boundaries, start/end byte addresses, and layout.                           |
| `qspi_image_jic.rpd`                | Raw Programming Data binary containing the full byte-level flash memory image for direct QSPI flash writers or flash emulators.                     |

!!! note
    Pre-built Binaries target the QSPI memory as boot media

Add the Simics installation path to your system `PATH` variable. The command below assumes an installation in the current user home directory. Adjust the path as required:

```bash
export PATH=~/altera_pro/intel-fpga-ext_26.3/simics/bin/:$PATH
```

### Deploy the Simics Virtual Platform

Follow the steps below to create a simulation workspace, deploy the Agilex 5 E-Series Universal Virtual Platform, and generate the top-level launch script.

**Step 1: Create Workspace Directory -** Create a workspace directory for simulation:

```bash
mkdir agilex5_zgsrd
cd agilex5_zgsrd
export CWD=$(pwd)
```

**Step 2: Deploy Virtual Platform -** Deploy an instance of the `agilex5e-universal` virtual platform:

```bash
cd $CWD
rm -rf zgsrd-agilex5e-universal
mkdir zgsrd-agilex5e-universal
cd zgsrd-agilex5e-universal
simics_intelfpga_cli --deploy agilex5e-universal
```

Expected output transcript:

```text
Simics(R) Simulator for Intel(R) FPGA CLI: 

INFO: Preparing to initialize /home/altera/tasks/projects/zephyr/simics/agilex5_zgsrd/tmp as a Simics workspace
Project created successfully
```

Compile the virtual platform modules:

```bash
make
```

This build step compiles the local virtual platform modules in `$CWD/zgsrd-agilex5e-universal` and prepares the `./simics` launcher script.

**Step 3: Configure Virtual Platform Execution Script -** Set the `cputype` environment variable to designate the boot core type (`a55` or `a76`).

```bash
export cputype=a55
```

The script below assigns the core configuration and sets the boot artifacts to target the `qspi_bin` folder.

```bash
cd $CWD/zgsrd-agilex5e-universal
cputypestring=""
if [ "$cputype" = "a76" ]; then
cputypestring='$hps_boot_core = 2
$hps_core0_1_power_on = TRUE
$hps_core2_power_on = TRUE
$hps_core3_power_on = TRUE'
fi

# Create zephyr_qspi.simics virtual platform configuration file 
# Add paths to boot artifacts
tee zephyr_qspi.simics << 'EOF'
# TOP-LEVEL CONFIG Script TO BOOT ZEPHYR.
local $board_name = "system.board.fpga"
# First stage boot loader, ATF BL2 path
$fsbl_image_filename = ../qspi_bin_prebuilt/bl2.bin
# Boot from QSPI
$qspi_image_filename = ../qspi_bin_prebuilt/qspi_image_jic.rpd
# Enable Serial Console
$create_hps_serial0_console=TRUE
EOF
# Add CPU parameter 
echo "$cputypestring" >> zephyr_qspi.simics
# Add start execution simics command
echo 'run-script "targets/agilex5e-universal/agilex5e-universal.simics"' >> zephyr_qspi.simics
```

For more parameter details, consult Chapter [2.1.3 Agilex™ 5 Universal Virtual Platform User-Configurable Parameters](https://docs.altera.com/r/docs/786901/25.3/intel-simics-simulator-for-altera-fpgas-agilextm-5-and-agilextm-3-virtual-platform-user-guide/agilextm-5-universal-virtual-platform-user-configurable-parameters) of the Intel® Simics® Simulator for Altera FPGAs Agilex™ 5 and Agilex™ 3 Virtual Platform User Guide.

## Compiling from Source and Testing

Follow the steps in this section to set up the toolchain, compile Zephyr and Arm Trusted Firmware (ATF) from source, and package an RTOS application into a bootable image using the Quartus Programming File Generator, and execute the resulting binaries in the Simics simulator.

The procedure is described for booting Zephyr OS from a SD card or QSPI memory.

### Environment Setup for Source Compilation

Prepare the host build environment by installing required system packages, configuring the Arm GNU and Zephyr SDK toolchains, and retrieving the reference FPGA bitstream.

**Step 1: Install System Dependencies -** Install system tool dependencies:

```bash

```

**Step 2: Establish Workspace Staging Area -** Establish workspace staging area:

```bash
mkdir -p agilex5_zgsrd
cd agilex5_zgsrd
export CWD=$(pwd)
```

**Step 3: Set Up Arm GNU Toolchain -** Download and register the Arm GNU toolchain:  

```bash
cd $CWD
wget https://developer.arm.com/-/media/Files/downloads/gnu/14.3.rel1/binrel/\
arm-gnu-toolchain-14.3.rel1-x86_64-aarch64-none-linux-gnu.tar.xz
```

**Step 4: Retrieve Baseline FPGA Bitstream -** Retrieve baseline FPGA bitstream.

Simics executes the HPS processor and peripherals in simulation without programming the physical FPGA logic fabric. However, the Quartus Programming File Generator (`quartus_pfg`) requires an SRAM Object File (`.sof`) header to construct the virtual QSPI configuration file (`.jic`/`.rpd`).


```bash
export ZEPHYR_SDK_INSTALL_DIR=$(pwd)
export ZEPHYR_TOOLCHAIN_VARIANT=zephyr
```

### Create Simics Zephyr Boot Artifacts

=== "Boot from QSPI"

    The virtual platform boots from a simulated QSPI flash model. To construct this image, `fiptool` packages the Secure Monitor (`bl31.bin`) and non-secure OS (`zephyr.bin`) into a single Firmware Image Package (`fip.bin`). The Quartus Programming File Generator then maps `bl2.hex` into initial boot sectors and places `fip.bin` at offset `0x03C00000`.

    **Step 1: Stage FIP Container -** Stage ATF and Zephyr payloads into a unified FIP container:

    ```bash
    cd $CWD
    mkdir -p qspi_bin && cd qspi_bin
    cp $CWD/arm-trusted-firmware-qspi/build/agilex5/release/bl2.bin .
    $CWD/fiptool create --soc-fw $CWD/arm-trusted-firmware-qspi/build/agilex5/release/bl31.bin --nt-fw $CWD/zephyrproject/zephyr/agilex5/zephyr/zephyr.bin fip.bin
    ```

=== "Boot from NAND"

    The virtual platform boots from a simulated NAND memory model. To construct this image, `fiptool` packages the Secure Monitor (`bl31.bin`) and non-secure OS (`zephyr.bin`) into a single Firmware Image Package (`fip.bin`).

    **Step 1: Stage FIP Container -** Stage ATF and Zephyr payloads into a unified FIP container:

    ```bash
    cd $CWD
    mkdir -p nand_bin && cd nand_bin
    cp $CWD/arm-trusted-firmware-nand/build/agilex5/release/bl2.bin .
    $CWD/fiptool create --soc-fw $CWD/arm-trusted-firmware-nand/build/agilex5/release/bl31.bin --nt-fw $CWD/zephyrproject/zephyr/agilex5/zephyr/zephyr.bin fip.bin
    ```

    **Step 2: Create the NAND image file -** Package `fip.bin` into `nand_mem.img`:

    ```bash
    cd $TOP_FOLDER/nand_bin
    dd if=/dev/zero count=8 bs=16MB | tr '\0' '\377' > nand_mem.img
    dd if=fip.bin of=nand_mem.img conv=notrunc bs=1 seek=2097152
    ```

    Exit the Python virtual environment:

    ```bash
    deactivate
    ```

    This command generates the `$CWD/nand_bin/nand_mem.img` programming image.

## Troubleshooting

This section provides solutions for common environment configuration and build directory issues encountered when setting up and compiling the Zephyr workspace.

### Sphinx Dependency Conflict During Environment Setup

Installing Sphinx packages on non-standard host Python environments can trigger version incompatibility conflicts with `docutils`:

```text
ERROR: sphinx-tabs 3.4.1 has requirement docutils~=0.18.0, but you'll have docutils 0.19 which is incompatible.
ERROR: sphinx-rtd-theme 1.2.2 has requirement docutils<0.19, but you'll have docutils 0.19 which is incompatible
```

Resolve the dependency pin by reinstalling the core documentation packages within the active Python environment:

```bash
pip install sphinx-rtd-theme sphinx
```

### Stale Build Artifacts When Recompiling Applications

Rebuilding alternate Zephyr applications inside an existing build directory causes configuration mismatch errors:

```text
ERROR: Build directory ".../zephyr/agilex5" is for application ".../hello_world", but source directory ".../blinky" was specified; please clean it, use --pristine, or use --build-dir to set another build directory
```

Force a clean build using the `-p always` flag:

```bash
west build -p always -b intel_socfpga_agilex5_socdk samples/hello_world -d agilex5
```
